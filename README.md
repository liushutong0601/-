# 自动搜题 · 学习通章节测验

版本：v1.1.3

适用系统：64 位 Windows 10 / Windows 11  
浏览器：Microsoft Edge

软件已内置 Python、AI 调用组件和浏览器控制组件，解压即用，不需要安装 Python、pip、openai 或 requirements.txt。

本软件通过学习通右侧目录识别未完成小节，自动进入“章节测验 / 章节检测 / 测验”，调用 AI 解答支持的选择题，并在答案完整、填写复核通过后提交。如果常规入口没有发现题目，会逐一点击同排任务标签排查；它只处理题目，不播放视频或完成其他任务点。

> AI 答案可能出错。真实提交无法由软件撤回，请先使用测试模式确认页面、题型和答案填写均正常。

## 一、直接使用（不需要安装 Python）

1. 将收到的 ZIP 压缩包**完整解压**，不要只把 `自动搜题.exe` 单独拖出来。
2. 双击解压目录中的 `自动搜题.exe`。
3. 选择 DeepSeek 或 Kimi，并填写对应开放平台的 API Key。
   - DeepSeek 默认模型：`deepseek-flash`
   - Kimi 默认模型：`kimi-k2.6`
   - 开放平台 API 与 Kimi / DeepSeek 聊天账号不是同一套调用凭证，费用和额度以对应开放平台为准。
4. 点击“启动学习通浏览器”。首次启动会打开软件专用 Edge，不会修改你日常 Edge 的主页、默认搜索引擎或收藏夹。
5. 在专用 Edge 中登录学习通，打开课程，手动进入准备开始答题的第一个小节。无需先进入章节测验，软件会自动查找该标签。
6. 建议先选“测试模式（只填写，不提交）”，点击“开始答题”。确认运行正常后，再改用“真实提交模式”。
7. 开始后会自动检测浏览器、当前页面和章节目录，运行日志始终显示在主窗口中，不需要再手动点击“测试连接”。

API Key 只保存在当前窗口内存中，不写入 README、日志或配置文件。关闭软件后需要重新填写。不要把含有 Key 的截图或聊天记录发给别人。

## 二、答题规则

- 右侧目录绿勾：视为已完成，直接跳过。
- 右侧目录黄圈 / 待完成任务点：进入该小节，优先查找“章节测验 / 章节检测 / 测验”标签。
- 常规入口没有题目：按页面原顺序逐一点击视频、资料等其他同排任务标签，直到发现可见题目；隐藏的旧题目不计入当前测验。
- 学习目标、视频、资料等页面只用于切换排查，不播放视频，也不完成其他类型任务点。
- 当前小节所有标签均没有测验：继续寻找下一未完成小节。
- 网页加载较慢时，会等当前小节题量和选项完整。若测验或任务页签加载超时，程序会停在当前小节，页面就绪后可点“重新检测并继续”。
- “测验”“章节测验”“章节检测”共用提交步骤。真实提交模式会等待提交按钮可用、确认弹窗出现和结果更新。
- 支持题型：单选题、多选题、判断题。
- 暂不支持：填空题、材料题、题目中带图片的题，以及无法可靠识别结构的页面；这些题会被跳过或使该小节停止提交。
- 只有全部题目都取得有效答案时才填写；只有填写后逐项复核一致时才允许真实提交。
- 例如 5 道题只得到 4 道有效答案，软件不会提交这一小节，而会继续后续小节。
- 所有目录小节处理完毕后显示“答题完成”。默认 5 秒后只退出答题软件，**不会关闭 Edge**。
- 手动停止、答案或页面异常、提交结果不确定时不会自动退出，窗口会保留原因和解决方法。

测试模式会填写并复核答案，但不会点击真实提交，然后继续后续小节。真实提交模式每次启动前都需要再次确认。

## 三、日志与运行速度

主窗口中的日志会显示：浏览器连接、当前章节、题目数量、AI 答案数量、填写复核、提交结果、跳过原因和最终统计。

Kimi 默认限制请求间隔约 21 秒，出现等待或遇到 429 后自动退避重试属于正常现象，不要连续快速重启。不同 AI 服务、网络和题目数量会影响总耗时。

软件运行记录位于：

```text
%LOCALAPPDATA%\AutoQuiz\logs
```

专用浏览器登录数据位于：

```text
%LOCALAPPDATA%\AutoQuiz\edge-profile
```

日常 Edge 的账号和浏览数据不会复制到该目录。若专用 Edge 登录状态异常，可先关闭软件和专用 Edge，再重命名上述 `edge-profile` 目录后重新启动；重新启动后需要重新登录。

## 四、常见错误与解决方法

软件通常会在窗口下方直接显示“发生了什么、可能原因、解决方法”，处理后点击“重新检测并继续”。

| 提示 | 可能原因 | 处理方法 |
| --- | --- | --- |
| API Key 缺失、401、认证失败 | Key 未填、复制不完整，或与服务商不匹配 | 到所选服务商的开放平台重新复制完整 Key，不要附带中文说明、引号或空格 |
| 模型 404、Not found、Permission denied | 模型名错误或账号没有该模型权限 | 展开“高级设置 / 诊断”，恢复默认模型；仍失败则检查开放平台权限和额度 |
| 429、请求频率受限 | 单位时间请求额度已用完 | 等待 1～2 分钟再继续；软件已自动限速和重试，无需频繁重启 |
| 无法启动或连接 Edge | 专用 Edge 未就绪、端口被占用或调试地址被改错 | 点击“启动学习通浏览器”；关闭专用 Edge 后重试；高级设置中的地址恢复为 `http://127.0.0.1:9222` |
| 未检测到学习通小节页面 | 当前标签不是课程学习页或尚未登录 | 在专用 Edge 中登录，打开课程并进入起始小节，再继续 |
| 有效答案不足、填写复核未通过 | AI 返回答案不完整，或页面选项未正确选中 | 软件已禁止提交；重试该小节，反复失败时跳过并查看完整日志 |
| 未识别确认弹窗、提交后未识别结果页 | 网页结构变化、网络延迟，或提交结果不确定 | 先人工查看页面，不要盲目重复提交；确认未提交后再重试，已提交则等目录出现绿勾 |
| 章节导航停在原处、页面无法读取 | 页面正在加载、结构变化或网络不稳定 | 保持网络稳定，不要手动刷新，稍后重试；仍失败时复制错误信息和日志 |

“复制错误信息”便于反馈问题；“打开完整日志”可查看本次运行记录。日志默认不包含 API Key，但可能包含课程网址和章节信息，分享前请先检查。

## 五、高级设置 / 诊断

一般使用不需要展开此区域。

- Edge 调试地址：默认 `http://127.0.0.1:9222`。
- 模型：仅在你明确知道账号可用模型名称时修改。
- 诊断：测试连接：只检测浏览器连接，不调用 AI。
- 诊断：解析当前章节：读取当前测验结构，不调用 AI、不填写、不提交。

开始答题时已经自动执行必要检测，因此这些按钮只用于排错。

## 六、如何更新

本版本不包含在线自动更新。后续更新方式如下：

1. 关闭旧版软件和专用 Edge。
2. 妥善保存自己的 API Key；不要把 Key 发给软件接收者以外的任何人。
3. 下载并完整解压新版 ZIP，使用新版目录中的 `自动搜题.exe`。建议整个目录替换，不要混用新旧 `_internal` 文件。
4. 原运行日志和专用浏览器登录数据保存在 `%LOCALAPPDATA%\AutoQuiz`，不随程序目录替换而删除；首次打开新版后重新填写 API Key 即可。

项目保留源码、自动化测试和版本号。后续需要修改时，可以直接在原有开发对话中提出需求，修改源码、运行测试并重新打包。软件界面标题会显示版本号，便于确认正在使用哪一版。

## 七、源码开发与重新打包（给维护者）

普通使用者无需执行本节。

项目架构、当前限制与学生团队分工见 [项目现状与团队分工](docs/项目现状与团队分工.md)。
Codex 网络排障、配置备份和插件安装结果见 [规则模式修复记录](docs/Codex规则模式修复记录.md)。
新电脑先创建 Python 3.12 虚拟环境，再安装已验证的开发依赖：

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe app.py --dependency-check
.venv\Scripts\python.exe tools/run_checks.py
```

完整检查使用独立无头 Edge 和本地合成页面，不调用在线 AI、不操作课程账号；零测试或跳过测试会使检查失败。GitHub Actions 的 Windows 检查配置位于 `.github/workflows/windows-tests.yml`，提交到远端后才能验证云端运行结果。

Git 忽略本地虚拟环境、构建产物、浏览器资料、课程截图和日志。源码运行的日志在项目 `logs` 中，发布版使用上述 `%LOCALAPPDATA%` 路径。

```bat
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean autoquiz.spec
```

开发环境运行：

```bat
.venv\Scripts\python.exe app.py
```

默认打包结果为 `dist\自动搜题\自动搜题.exe`。发布时应压缩整个 `自动搜题` 目录，确保发布包不含开发机的 `.edge-debug-profile`、`logs`、课程截图或任何 Key。

本次 v1.1.3 构建使用 `--distpath dist\v1.1.3`，生成的软件位于 `dist\v1.1.3\自动搜题`。使用 `.venv\Scripts\python.exe -m tools.package_release --app-dir dist\v1.1.3\自动搜题` 可从这个目录生成发布 ZIP。

生成发布 ZIP 前，还应对新 EXE 分别执行 `--dependency-check` 和 `--smoke-test`，确认运行组件和窗口启动均正常；仅源码测试通过不能替代冻结版验收。然后运行 `.venv\Scripts\python.exe -m tools.package_release`，生成带版本号的完整压缩包并执行 ZIP 完整性检查。
